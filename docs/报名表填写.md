### 2. 你做过什么项目？（必填，上限 3000 字，本段约 780 字）

```
BeatDancer：让机器人听懂音乐、自己编舞

一句话：输入任意一首歌，系统在 0.4 秒内完成「听歌 → 理解结构 → 编排动作 → 生成 16 个关节的 50Hz 轨迹」，机器人不需要预先编好的舞，换歌就能跳。目前全流程已跑通并开源，下一步是把它落到 RDK X5 + 16 舵机人形上。

我负责四个环节的设计与实现：

1）听觉层（纯 numpy，不依赖 librosa/torch，可直接上板）：对数梅尔谱 → 谱通量 onset → 自相关估计速度 → 动态规划追拍（Ellis 算法）→ 用「脉冲串对齐」把拍点网格吸到真实鼓点上，再做小节级纹理变点检测切出 intro / verse / chorus / outro。实测 124 BPM 原创曲上 BPM 误差 0.02%，分析耗时 0.36 秒（约 100 倍实时）。

2）编舞层：设计 20 个参数化动作基元（点步、摆胯、踢腿、转体、跳跃等），每个基元标注「几拍 / 能量 / 是否腾空 / 支撑脚」。用带记忆的动态规划在乐句上求最优动作序列，代价函数 = 能量匹配 + 相邻动作衔接距离 + 连续重复惩罚；段落第一句作为「动机」，后半段用镜像与同类替换做呼应，副歌因此有记忆点，而不是随机堆动作。

3）身体层：16 自由度人形正向运动学 + 关节限位；50Hz 采样后做接缝交叉淡化、角速度限幅（0.22 rad/帧，保护舵机）、足底贴地（腿弯时抬胯，而不是让脚穿进地板）。

4）执行层：Feetech STS 总线，一条 SYNC_WRITE 广播包同时驱动 16 个舵机；live 模式用 10ms 帧的实时节拍跟踪驱动即兴选动作，断拍 2 秒自动回到安全姿态。

完成情况：35 秒的曲子生成 21 个动作段、1767 帧轨迹；导出 servo_table.csv（0–1000 tick）、BVH（可直接进 Blender）、Unitree G1 轨迹；带音轨演示视频与单文件网页 Demo 已完成；11 个单元测试覆盖 BPM 精度、动作覆盖性、关节限位与足底约束，全部通过。

本次参赛目标：48 小时内把同一套代码落到真机上，完成「真机跳舞 + 现场随便放一首歌即兴跳 + 观众拍手机器人接拍」三段演示。
```
